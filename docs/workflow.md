# Коммиты и выпуск

Для каждой задачи используй рабочую ветку. Если задачу начали в чате, к первому коммиту подбери её существующий идентификатор или присвой новый свободный номер в [бэклоге](backlog.json).

1. Начинай сообщение каждого коммита с идентификатора задачи. Пример — `[SS-006]: Приглушать видео во время разговора`. Обычно хватает одной строки. Добавляй абзац только для существенной детали.
2. Для вливания открой pull request в `main`. Заголовок PR и итогового коммита следуют тому же формату. Кратко опиши результат и проверки.
3. Перед согласованным вливанием проверь diff, успешный CI для текущей вершины PR и результат ручной приёмки, если она нужна. Выполни **Squash and merge** для проверенного коммита.
4. Обнови сведения об `origin/main` и тегах. На итоговом squash-коммите создай аннотированный тег и опубликуй его. Первый тег — `v0.1.0`, каждое следующее вливание увеличивает patch на один. При повторе используй тег этого же вливания. Опубликованные теги не перезаписывай.
5. Сверь опубликованный тег с SHA squash-коммита и убедись, что коммит входит в `origin/main`. Если в рабочей ветке нет новых коммитов после проверенной вершины PR, перейди на актуальную `main` и удали завершённую ветку локально и на GitHub.

Согласие на вливание включает публикацию тега и удаление завершённой ветки. В ответе укажи PR, тег и результат очистки.
