# SS-009: Устранить предупреждение безопасности SignalR/.NET

Статус: blocked. Ветка серии: `fix/backlog-priority-five`.

## Критерии приёмки

- Обновить SDK и ASP.NET Core runtime до выпуска с исправлением GHSA-334f-vvp4-7g6p.
- Обновить затронутые Microsoft.AspNetCore пакеты, согласовать lock-файлы, CI и Docker.
- Полный harness и контейнерная сборка проходят без NU1903 по этому бюллетеню.

## Проверка

Регрессионная проверка до исправления, затем подходящие клиентские/доменные/интеграционные проверки и `npm run check:full`. Фактические отчёты и ограничения будут внесены после выполнения.

## Состояние рабочей копии

Предыдущие незакоммиченные изменения harness, SS-006 и SS-004 сохраняются. Коммиты, публикация и production-окружение не входят в эту серию.

## Препятствие проверки

16 октября 2026 года официальные метаданные подтвердили исправление в ASP.NET Core/SignalR 10.0.13 и SDK 10.0.113 (та же feature band, что 10.0.102). Локальная загрузка builds.dotnet.microsoft.com завершилась `Resolving timed out`, Azure Blob и dot.net — `SSL connection timeout`, NuGet flat-container — `Resolving timed out`. В кэше есть только SignalR 10.0.6. Версии и lock-файлы не менялись, чтобы не оставлять непроверяемую сборку.

Источники: [бюллетень Microsoft](https://github.com/advisories/GHSA-334f-vvp4-7g6p), [официальные метаданные .NET 10](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json). Для завершения нужны доступные загрузки SDK/пакетов, полный harness и контейнерная сборка. Проверки исходной уязвимой версии всё ещё дают NU1903; задача не считается выполненной.

Повторная загрузка официального архива SDK 10.0.113 в конце проверки SS-005 также завершилась `Resolving timed out after 10004 milliseconds`. SS-009 остаётся blocked; вместо неё пятая задача серии — SS-008.
