# SS-001: Подтверждённая сервером сессия участника

Статус: done. Ветка серии: `fix/backlog-priority-five`.

## Критерии приёмки

- Сервер выдаёт непредсказуемое подтверждение сессии; известного UserId недостаточно для HTTP-команд и Hub.
- HTTP и Hub проверяют членство и права; SendSignal определяет отправителя по соединению.
- Hub не создаёт участника и не обходит лимит четыре; регрессии проверяют подмену и постороннего участника.

## Проверка

Регрессионная проверка до исправления, затем подходящие клиентские/доменные/интеграционные проверки и `npm run check:full`. Фактические отчёты и ограничения будут внесены после выполнения.

## Состояние рабочей копии

Предыдущие незакоммиченные изменения harness, SS-006 и SS-004 сохраняются. Коммиты, публикация и production-окружение не входят в эту серию.

## Реализация и проверка

Сервер выдаёт собственный UUID и Data Protection bearer-токен на сутки через `/api/session`. Браузер сохраняет сессию в sessionStorage и использует её в HTTP и SignalR. Переданный UserId проверяется относительно подтверждённой сессии; знание публичного UUID не даёт права действовать от его имени. Снимок требует членства. Hub не создаёт участника, проверяет актуальную привязку соединения, комнату и адресата; отправитель сигнала определяется сервером. Завершение старого соединения не удаляет заменившее его соединение.

Одновременные изменения состава и состояния комнаты сериализованы в одном процессе API. Для горизонтального масштабирования потребуется общая блокировка в БД. Data Protection key ring необходимо сохранять при пересоздании production-контейнера. Сессии гостевые, без аккаунтов и восстановления утраченного токена.
