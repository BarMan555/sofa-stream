# SS-005: Управление длинными видео и ошибки команд

Статус: done. Ветка серии: `fix/backlog-priority-five`.

## Критерии приёмки

- Длительность берётся из метаданных видео, а не из константы 3600.
- Пауза и перемотка после первого часа сохраняются сервером и применяются гостем.
- HTTP-отказ или ошибка сети показаны пользователю, клиент повторно получает авторитетное состояние.

## Реализация и проверка

Вместо константы 3600 новое видео получает длительность 0 — метаданные пока неизвестны. Ведущий сохраняет действительную положительную длительность плеера через `/video/duration`, с проверкой членства, роли и версии видео. Обновление не перезапускает видео и не сбрасывает позицию. Пока метаданных нет, сервер не вводит искусственный верхний предел; затем проверяет настоящую границу. Некорректные длительности и старые версии отклоняются.

Позиция HTTP-команды сохраняет миллисекунды и поддерживает префикс дней TimeSpan. При HTTP-отказе и сетевой ошибке клиент показывает причину, получает авторитетный снимок и возвращает локальный плеер к состоянию сервера без повторной настройки WebRTC. Запоздалая команда другого видео отклоняется.

До исправления обе браузерные регрессии упали: позиция 3610 отклонялась сервером, отказ команды оставался без уведомления/отката. Отчёт: `artifacts/harness/2026-10-16T14-47-24-873Z-78298-1/summary.json`.

Внешний YouTube выявил два взаимодействия с SS-003: загрузка кадра на паузе оставляла флаг ожидания, а краткий Buffering при выполнении Play вызывал цикл общей паузы/старта. Paused больше не создаёт такой флаг. Во время применения удалённой команды краткие переходы подавляются; после окна применения проверяется, продолжается ли загрузка. Если общая буферизация уже началась, собственная продолжающаяся загрузка учитывается до паузы. Обе причины закреплены регрессионными тестами; браузерный плеер получил режим короткой нативной загрузки.

Итоговый `npm run check:full`: 20 unit + 36 frontend + 3 harness + 26 integration + 17 browser = 102. Отчёт: `artifacts/harness/2026-10-16T15-03-39-593Z-90313-1/summary.json`. Проверены два участника, перемотка 3610, HTTP-отказ, сетевая ошибка и следующая успешная команда. Пропусков/нестабильных браузерных результатов нет.

Настоящий [Google I/O Keynote 2017](https://www.youtube.com/watch?v=Y2VF8tmLFHw) отдельно прошёл получение длительности, перемотку на 3610, Play и Pause в Chromium без подмены Iframe API. Отчёт: `artifacts/harness/2026-10-16T15-03-38-456Z-89891-1/summary.json`; снимок `youtube-after-first-hour.png`, trace и browser-console. YouTube сначала возвращал округлённые 7002 с, затем уточнил метаданные до 7001,461 с; сервер сохраняет уточнённое значение. Сравнивается текущая длительность, а не первоначальное округление. [Документация Iframe API](https://developers.google.com/youtube/iframe_api_reference).

## Границы проверки

Основной набор подтверждает синхронизацию двух участников с настоящими HTTP/SignalR/PostgreSQL и управляемым внешним плеером. Внешний успешный сценарий использует один настоящий YouTube-плеер и синтетические камера/микрофон; субъективное прослушивание не проводилось. Попытка с двумя настоящими плеерами выявила старый четырёхсекундный fallback загрузки YouTube API у второго браузера (SS-007); это не считается успешной проверкой двух настоящих плееров. RuTube вживую не проверялся. Одноразовый внешний сценарий не входит в регулярный `check:full`.
