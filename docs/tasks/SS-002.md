# SS-002: Восстановление комнаты после обрыва связи

Статус: done. Ветка серии: `fix/backlog-priority-five`.

## Критерии приёмки

- Повторное соединение подтверждает ту же сессию, восстанавливает группу и актуальный снимок.
- Старое отключение не удаляет участника нового соединения.
- Краткий обрыв сохраняет ведущего в заданном окне; явный выход удаляет участника сразу, истечение окна передаёт роль.

## Проверка

## Состояние рабочей копии

Предыдущие незакоммиченные изменения harness, SS-006 и SS-004 сохраняются. Коммиты, публикация и production-окружение не входят в эту серию.

## Реализация и проверка

Отключение сохраняет членство и роль на 30 секунд. `Rooms:ReconnectGraceSeconds` задаёт окно 1–300 секунд. PostgreSQL хранит `DisconnectedAt`; фоновый обработчик удаляет просроченных участников, передаёт роль и удаляет пустые комнаты. При запуске процесса старые соединения получают такое же окно. Добавлена миграция `20261016142500_TrackDisconnectedParticipants`.

Новое соединение перезаписывает ConnectionId и снимает ожидание. Обработка старого отключения ищет только его ConnectionId. HTTP `/leave` и Hub `LeaveRoom` обеспечивают немедленный явный выход. Клиент при восстановлении повторяет admission/Hub join, получает снимок и роль, отменяет прежние действия и заново устанавливает локальные peer-соединения. Выход защищён от запоздалых результатов восстановления и первоначального входа.

До исправления регрессия короткого обрыва не смогла восстановить членство: `artifacts/harness/2026-10-16T14-21-08-839Z-62429-1/summary.json`. Серверные тесты проверяют границу 29/31 секунды, реальную фоновую передачу роли и удаление пустой комнаты. Клиентский тест проверяет выход во время незавершённого восстановления.

Итоговый `npm run check:full`: 13 unit + 28 frontend + 3 harness + 24 integration + 10 browser = 78, без пропусков и нестабильных результатов. Отчёт: `artifacts/harness/2026-10-16T14-33-54-247Z-70766-1/summary.json`.

В браузерном сценарии WebSocket прозрачно соединён с настоящим сервером и явно разрывается при запрете новых сетевых запросов; затем сеть возвращается. Результат проверяет новый ConnectionId, состав комнаты, роль, текущую позицию и следующую команду паузы. Первоначальный способ через один `setOffline` не оборвал уже открытый локальный сокет; следующий запуск выявил необходимость установить маршрутизацию до загрузки SignalR. Никакие Hub-ответы или обработчики переподключения не подменяются. [API WebSocketRoute](https://playwright.dev/docs/api/class-websocketroute).

Проверено на локальном PostgreSQL и Chromium с управляемым плеером. Связь между разными сетями и слышимость не подтверждались; это остаётся SS-007. Окружение итогового запуска очищено.
