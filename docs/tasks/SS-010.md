# SS-010: первое видео самопроизвольно играет у гостя

Статус: done. Ветка: `fix/backlog-priority-five`. Проверено 17 октября 2026 года (Europe/Samara).

Пользовательская проверка: оба участника уже в комнате, ведущий впервые загружает YouTube. У ведущего видео ожидает Play, у гостя играет; на снимке гостя шкала остаётся `00:00 / 00:00`.

## Критерии приёмки

- Первая загрузка и смена видео оставляют обоих участников на паузе до команды ведущего.
- Медленный или недоступный YouTube API не включает независимый iframe с автозапуском и нулевой шкалой.
- Поздняя готовность API восстанавливает управляемый плеер с последним видео и актуальным состоянием комнаты без перезагрузки страницы.
- Позднее нативное Playing не отменяет серверную паузу; следующий разрешённый Play/Pause продолжает работать.
- RuTube сохраняет возможность загрузиться при недоступном YouTube API; полная внешняя совместимость остаётся SS-007.

## Регрессия до исправления

`node --test tests/frontend/youtube-loading.test.mjs tests/frontend/player-readiness.test.mjs`: четыре новых проверки упали. Подтверждены независимый autoplay iframe, игнорирование позднего API, отсутствие безопасного состояния при ошибке загрузки и принятие позднего Playing при Paused.

Снимок согласуется с независимым iframe, но без диагностики вкладки нельзя утверждать, какой из путей сработал у пользователя. Исправление покрывает оба пути.

Отдельная регрессия выявила лишний seekTo(0) при применении Paused-снимка к уже подготовленному видео на нуле. По [документации YouTube](https://developers.google.com/youtube/iframe_api_reference#seekTo) seekTo из CUED запускает воспроизведение. Совпадающая позиция больше не требует такого вызова.

## Реализация

Удалены самостоятельный YouTube embed с autoplay и StubPlayer. Комната и RuTube доступны во время ожидания YouTube, но команды видео ожидают его настоящей готовности. Поздний API инициализируется в том же адаптере без потери последнего выбранного видео. Сообщение показывает ожидание или ошибку загрузки. Первая загрузка и смена видео не начинают просмотр сами; поздний Playing при Paused или до запланированного старта возвращается на паузу. Новые адреса player.js, sync.js и app.js используют версию 1.9.

При повторной проверке обнаружен отдельный дефект локальной сборки: сгенерированные JSON из bin попадали в Content и рекурсивно копировались обратно в bin, пока путь не превышал допустимую длину. В API явно исключены bin/** и obj/** из Content. Проверка фактических элементов MSBuild после изменения: один appsettings.json, ноль сгенерированных файлов. Удалены только вложенные результаты сборки в bin, исходники и пользовательские настройки сохранены.
