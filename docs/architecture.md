# Архитектура SofaStream

Браузеры воспроизводят YouTube и RuTube у себя. API хранит состояние комнат в PostgreSQL и синхронизирует участников через SignalR. Звук и видео звонка идут через WebRTC, сигналы для соединения передаёт RoomHub.

| Где | Что искать |
| --- | --- |
| `SofaStream.Domain` | Агрегат `Room`, участники, ведущий и правила воспроизведения |
| `SofaStream.Application` | Команды, запросы, DTO и обработчики доменных событий |
| `SofaStream.Infrastructure` | EF Core для записи и миграций, Dapper для чтения состояния |
| `SofaStream.Api` | HTTP, гостевые сессии, RoomHub и жизненный цикл соединений |
| `Frontend` | HTML/CSS/JS, адаптеры видео, синхронизация, видеочат и управление |

HTTP-команда меняет состояние комнаты, EF сохраняет его, затем SignalR рассылает событие. Вход и переподключение восстанавливают отдельный HTTP-снимок. При изменении синхронизации учитывай оба пути и готовность конкретного видео в адаптере. При паузе первого видео ведущий и гость ждут команды Play.

Членство и права проверяет сервер по гостевой сессии. Комната вмещает до четырёх участников. Короткий код служит для приглашения, UUID остаётся идентификатором в HTTP и SignalR. При обрыве связи есть 30 секунд на восстановление членства и роли ведущего по умолчанию.

`Frontend/js/webrtc.js` управляет соединениями и медиапотоками, `chat-ui.js` — отображением участников. Громкость фильма хранится локально и приглушается при речи без изменения положения ползунка.

Сценарии и история изменений собраны в [бэклоге](backlog.json).
